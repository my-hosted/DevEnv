# 运行配置平铺视图

## 背景

大项目通常需要同时启动多个运行配置、打开多个终端。当前「运行配置」页只支持左侧列表 + 右侧单个详情（终端）的布局，用户若要同时观察多个配置的终端，只能在多个配置之间来回切换，效率很低。

## 需求

当点击任意一个运行配置时，在右侧详情顶部「关闭详情」的左侧增加一个**平铺按钮**。点击后，把「运行配置」tab 下的所有运行配置以卡片网格的形式平铺到页面主体中。

1. **每行卡片数可调**：支持调整每行显示的卡片数，调整后网格自动重新排列。
2. **拖拽排序并记忆**：支持拖拽卡片调整排列位置，并记住排列结果；除非某个配置被删除，删除后其余卡片按删除前的相对顺序排列。
3. **卡片详情入口保留**：卡片上的详情按钮依旧保留，但只使用易于理解的 icon 按钮，让每张卡片保持整洁。
4. **面向终端总览**：平铺功能的核心目的是直观地同时看到所有运行配置的终端，方便大项目同时运行多个配置、启动多个终端。

## 验收标准

- [ ] 运行配置详情头部，在关闭按钮左侧出现平铺按钮，图标与提示文案清晰。
- [ ] 点击平铺按钮后，页面主体切换为卡片网格，每张卡片显示该运行配置的名称、状态、logo 与终端。
- [ ] 工具栏可调整每行卡片数（1–N），调整后立即重排。
- [ ] 可直接在卡片上启动/停止该配置的终端；终端已创建时卡片内实时显示终端输出。
- [ ] 卡片支持拖拽排序，顺序在工作区维度持久化，重新打开 App 后仍保留。
- [ ] 拖拽时显示浮动卡片预览，拖到目标卡片左/右半区出现插入指示条，**松手后**才实际换位。
- [ ] 每张卡片支持全屏：点击后该卡片铺满页面主体，退出后回到平铺网格。
- [ ] 配置被删除后，其余卡片保持删除前的相对顺序。
- [ ] 卡片详情按钮仅为图标，点击可切回列表/详情并定位到该配置。
- [ ] 平铺视图提供返回列表的入口，且切换到其他页面时自动退出平铺。

## 技术说明

- 排序是纯展示层的偏好：按工作区存储一份配置 ID 顺序（UserDefaults），不改变运行配置本身的持久化模型。
- 展示顺序 = 已存储顺序中仍存在的配置（保持相对顺序）+ 未记录过的新配置（追加）。
- 每行卡片数使用 `@AppStorage` 记忆。
